# Engineering Decisions

> Approved exceptions and project-wide engineering choices referenced by [RUST-STANDARDS.md](RUST-STANDARDS.md). Newest last.

| # | Date | Decision | Why |
|---|---|---|---|
| D-001 | 2026-10-28 | File size limits: code ≤ 400 lines / 64 KB, docs ≤ 1000 lines / 128 KB, data ≤ 512 KB, other files ≤ 1 MB; `Cargo.lock` exempt. Enforced by `tools/file_size_guard.py` (Claude hook, git pre-commit, `tools/check.sh`). Already-oversized files may be edited only if they don't grow. | Keeps modules single-purpose and reviewable |
| D-002 | 2026-10-28 | `unsafe` is forbidden in every library crate. The only exception is the counting global allocator in allocation-test integration targets (`tests/no_alloc.rs`), which needs `unsafe impl GlobalAlloc`. | Standard §10 and §13.5 |
| D-003 | 2026-10-28 | Floating-point transcendental functions use the pure-Rust `libm` crate, never `f64::sin` & co. | Platform libm results differ across OSes; golden hashes must match on macOS, Linux and Windows |
| D-004 | 2026-10-28 | M0 adds `px-expr` and `px-engine` to the five crates listed in ROADMAP so that expression evaluation and frame rendering each have one owner (SRP). | Keeps `px-format` a pure loader and `px-raster` a pure rasterizer |
| D-005 | 2026-10-28 | Commits and PRs carry no AI agent signature: no agent `Co-Authored-By`/`Signed-off-by`/`Assisted-by` trailers, no "Generated with …" footers, no `🤖`, no agent session links, no agent author or committer identity. Enforced by `tools/commit_guard.py` as a git `commit-msg` hook and by `tools/check.sh` over the whole history. | Project owner's rule: commits are authored by people |
| D-006 | 2026-10-28 | **No hosted CI.** No GitHub Actions or any other service that can generate costs. Every check runs locally with `tools/check.sh` before each push; wherever the docs say "CI", read `tools/check.sh`. Cross-platform hash checks run in a free local Linux container when needed; Windows stays unverified until a free option exists. | Project owner's rule: no costs |
| D-007 | 2026-10-28 | **Self-explanatory code, minimal comments.** No comments or doc comments that restate code; the `missing_docs` lint is off and clippy's `missing_errors_doc` / `missing_panics_doc` are allowed. Comments remain only for non-obvious *why*, invariants, `SAFETY`, spec references, test instructions and CLI help text. | Project owner's rule: "if code needs a comment to be understood, it is wrong" |
| D-008 | 2026-10-28 | **Zoom re-rasterizes, never resamples.** The camera `zoom` can be any value and animate smoothly: every shape is drawn again at the zoomed size (positions, sizes, radii, widths, light reach scale; outlines stay 1 px; dither stays on the screen grid; textures stay anchored to the shapes). This replaces the earlier "integer zoom, changed only by a cut" rule in DIRECTOR.md §3. | Shapes are vector descriptions, so a re-raster keeps every frame clean pixel art with no blur or uneven pixels; the project owner chose smooth zoom |
| D-009 | 2026-10-29 | **Sequences compose (shot, paint) cells; GIF frames carry their own color table.** A sequence frame stores, per pixel, the paint and the shot whose palette it belongs to; golden tests hash both. Transitions only choose between the two shots' pixels or step tones within one palette, never mix colors. A sequence's GIF gives every frame a local table of exactly the colors it shows (at most 256), instead of one global palette. | Shots keep their own palettes (a trailer cuts between scenes made in different palettes) while every pixel stays an exact palette color and hashing stays palette-independent |
| D-010 | 2026-10-30 | **Exports run in parallel in `px-cli`; the engine stays single-threaded.** `pxe export` renders and LZW-compresses fixed 16-frame chunks on `--jobs` threads, each with its own `FrameBuffer`/`Player`, and writes them in frame order. GIF frames are deltas: only the box that changed since the previous frame, with unchanged pixels transparent when the color table has a free slot. A worker re-renders the frame before its chunk as the delta reference, so the bytes never depend on the thread count. Renderer speedups must stay bit-identical (golden hashes unchanged): `px_core::floor` matches `libm::floor` exactly, and squared-distance shortcuts before `hypot` use margins far above float error. | Export was single-core and compressed every full ×4 frame; this keeps determinism (frame-order output, no scheduling-dependent bytes) and the allocation-free render contract |
| D-011 | 2026-10-30 | **Timeless shapes are drawn once and copied (stamps).** `Scene::new` renders one frame and records, for every shape whose evaluated values are all timeless (`Program::is_timeless`: no `t`/`f`, keyframes or time-driven function such as `osc`, `wiggle`, `wind`), the pixels it wrote together with its key: the canvas transform it was drawn through (camera, layer, instance, anchor) and its clip regions. A frame copies the stamp whenever the shape's key matches bit for bit and draws the shape otherwise, so a camera that zooms only for a while still reuses stamps the rest of the time. Shades, contact shadows and particles read the surface or the clock and are never stamped. Lighting and reflections still run every frame. Golden hashes are unchanged. | Most shapes in a scene don't animate; drawing them every frame was most of the frame time in small scenes and a large share in big ones |
| D-012 | 2026-10-30 | **The editor is drawn by the engine, not egui.** `px-ui` renders every UI pixel into an indexed canvas in a theme palette (a KDL file) with the engine's pixel font; icons are KDL scenes of `pixels` rendered by the engine; windows come from minifb (already a dependency). This replaces EDITOR.md §1's egui choice. | The editor itself is pixel art, uses no new dependency, and its look is data the engine renders |
| D-013 | 2026-10-30 | **Hand-painted pixels are `pixels` nodes in the scene file** (FORMAT appendix A.9): a legend of 1- or 2-character codes naming paints and cels as text grids per starting frame, cropped to their painted pixels. Rendering gives each pixel its own paint through the mask, so lighting, fog, outlines, clips and stamps apply as to shapes. | Painted and procedural art live in one diffable KDL file; no sidecar images |
| D-014 | 2026-10-30 | **The KDL text is the editor's source of truth.** Every edit (a stroke, a layer change, a click on a swatch, typing in the code view) splices the text at parser spans and reloads it (`px_format::edit::Source`); untouched bytes never change. Undo is a bounded history of whole texts, shared by the visual and code views. | Byte-stable files and one undo for both views, with no separate document model to keep in sync |
| D-015 | 2026-10-30 | **Editor architecture: domain / tools / views / app with ports and adapters.** `px-editor` (domain: documents, commands, history; tools: one `Tool` type each; views: panels that only emit `Intent`s; app: windows and dispatch) never touches windows or files: it asks `FileStore` and returns pixels; `px-cli`'s `pxe edit` is the only adapter (minifb, file system). `tools/check.sh` fails if `px-editor` or `px-ui` reach minifb or `std::fs`. | SOLID with the dependency rule enforced, and the whole editor testable headless |
| D-016 | 2026-11-01 | **Several documents open as tabs.** `App` holds a `Documents` set (`Vec<Slot>` plus the active index); the active document's `Editing` and main-window view live in `App` and are swapped into the slot on tab change, in one place (`tabs_ops.rs`). `RenderCache` keys on the `DocumentId`. The Home tab shows when nothing is open. Out of scope for now: frame tags, slices, trim, tilesets, per-layer sheets, `pxe export --format`. | Aseprite's most visible trait; one swap site keeps the 80-odd call sites simple |
| D-017 | 2026-11-01 | **Files are chosen with native OS dialogs**, the one exception to D-012. The app emits `Request::PickFile`; `pxe edit` answers with `rfd` on the main thread and feeds the path back as `Intent::Picked`. `tools/check.sh` forbids `rfd` in `px-editor`/`px-ui` as it forbids `minifb`. | Project owner's choice: the OS dialog knows the user's folders; headless tests dispatch `Picked` directly |
| D-018 | 2026-11-01 | **Transparent sprites by keyed render, classified by ramp.** The exporter clones the scene spec, pushes a one-tone key ramp, makes it the background, renders, and turns every cell still on that ramp transparent. | No engine change; lighting only shifts tones or swaps twinned ramps and fog touches shape pixels only, so background cells keep the key ramp while a sprite pixel painted with the real background paint stays opaque |
| D-019 | 2026-11-01 | **Sprite sheets compose at `u32` sides with their own RGBA PNG writer; `Size` stays per frame.** Metadata is Aseprite's JSON (hash format) written by a hand-written `JsonWriter` with fixed key order. Frame rendering stays in `px-editor`; `px-export` turns pixels into bytes only. | A 64-frame strip of 64 px is 4096 px, past `MAX_CANVAS_SIDE`; game engines read Aseprite JSON; no serde dependency and no `px-export` → `px-engine` edge |
| D-020 | 2026-11-01 | **Palette editing splices `ramp` lines through `Command`s; HSV and the ramp generator live in `px-core::hsv`.** Presets ship as embedded palette files (in-house, CC0). The scene format does not grow. | D-014: text is truth, one undo history; `libm` keeps generated colors identical on every OS |
| D-021 | 2026-11-01 | **Per-element code editing is `Command::ReplaceNode` over `Source::replace`; the element tree walks `Source` nodes**, not `Loaded.origins` (which exist only for painted shapes). After a replace the selection is re-resolved by offset, because an id change changes the node's own path. Nodes from `use`d files stay read-only. | Every KDL node becomes editable in place with a byte-stable diff |
| D-022 | 2026-11-01 | **Canvas Size is one compound `Command::ResizeCanvas`:** the scene's width and height plus every pixel layer's cels shifted by the anchor and cropped. | One undo step, as in Aseprite |
| D-023 | 2026-11-01 | **Editor state lives in `~/.config/px/editor.kdl`:** recent files, last folder, last export job, next to the layout. Untitled documents with unsaved changes are kept under `~/.config/px/unsaved/`. Scene files never carry editor state. | Editor preferences are per user, not per scene |
| D-024 | 2026-11-01 | **No comments in code, none at all.** No `//`, `///` or `//!` in Rust and no `#` lines in the Python and shell tools (shebangs aside); names, types, `#[expect(reason)]` attributes and assertion messages carry what comments used to. CLI help text moves to clap attributes. Enforced by `tools/comment_guard.py` in `tools/check.sh`; replaces the allowances of D-007. | Project owner's rule (2026-11-01): "no quiero ni uno solo, todo el código debe explicarse por sí mismo" |
| D-025 | 2026-11-01 | **High resolution is `detail`, a render setting that re-rasterizes.** `Detail` (1 to 8 in thousandths, so it is `Eq` and exact) is applied by `Scene::with_detail` and by `LoadOptions::detail`; the spec keeps the logical size, the canvas grows, and the camera transform scales by the detail, so D-008's re-raster rule gives real detail and nothing is ever resampled. Shadows march per scene-pixel block (⌊detail⌋², same depth) and reuse the result, and each ray is clipped to the shadow casters' bounding box (exact). The editor keeps rendered frames packed (`Paint::packed`, 2 bytes) up to a fixed budget and blits only the visible window rows. | RENDERING.md §16.3 asks for regeneration at a new size, not upscaling; a shadow march per output pixel made detail 4 cost 30× a native frame; the editor redrew every scene pixel through a clipped per-pixel block and re-rendered every played frame |
